# E-03 人事の回答だけ丁寧な文体にしたい

## 変更依頼

> 人事の回答だけ社外の人にも見せられる丁寧な文体にしたい

部門ごとの上書きがスキルで表現できるかを確かめる。

判定のマーカーは、回答の末尾に出る次の 1 文とした。

> ご不明な点がございましたら、人事部まであらためてお問い合わせください。

## 試した 3 つの方法

| 方法 | 人事に直接聞いたとき | ハブ経由 |
| --- | --- | --- |
| 1. 部門固有スキル `hr-tone` を人事エージェントに置く | **起動せず** | **効かず** |
| 2. 人事エージェントの指示に書く | **効いた** | **効かず** |
| 3. ハブの共通スキル `tone-and-format` に部門条件を書く | 該当なし | **効いた** |

### 方法 1: 部門固有スキル

`hr-tone` という部門固有スキルを作り、人事エージェントに追加した。

人事エージェントに直接聞いても `Loading skill: hr-tone` は出なかった。起動したのは `search-before-answer`、`hr-leave-procedure`、`analyzing-docx` の 3 つである。検証 C で `hr-leave-procedure` が直接なら起動したことを踏まえると、スキルが多いほど起動しにくくなる可能性がある。

ハブ経由でも当然、効かなかった。

### 方法 2: 部門の指示

人事エージェントの指示に次の 2 行を追加した。

```
回答は、社外の人が読んでも差し支えない丁寧な文体にしてください。依頼と案内は「〜してください」ではなく「〜いただきますようお願いいたします」と書いてください。
回答の最後に、「ご不明な点がございましたら、人事部まであらためてお問い合わせください。」を必ず書いてください。
```

**人事エージェントに直接聞くと、完全に効いた。**

> 年次有給休暇は、半日単位で**取得いただけます**。
> ...所属長へ**ご連絡いただき**、出勤後 3 営業日以内に事後申請**いただきますようお願いいたします**。
> **ご不明な点がございましたら、人事部まであらためてお問い合わせください。**

**ハブ経由では 1 つも効かなかった。** 文体は「〜します」のまま、末尾の 1 文も出なかった。

### 方法 3: ハブの共通スキルに部門条件

`tone-and-format` に次の節を追加して v4 とし、ハブだけ差し替えた。

```
## 部門ごとの文体

人事に関する回答では、次の 2 点を上書きします。ほかの部門では上書きしません。

- 依頼と案内は「〜してください」ではなく「〜いただきますようお願いいたします」と書きます。
- 受付時間の案内より後に、次の 1 文をそのまま置きます。

ご不明な点がございましたら、人事部まであらためてお問い合わせください。
```

**ハブ経由で効いた。**

- 人事 (有給は半日単位で取れますか): 「次にすること」が 3 項目とも「〜いただきますようお願いいたします」になり、末尾に該当の 1 文が出た
- 情報システム (VPN は公衆 Wi-Fi から使えますか): 文体は「〜します」のまま、末尾の 1 文も出なかった

**他部門に波及していない。** 部門ごとの上書きとして正しく働いている。

## 判定

**合格 (ただし方法 3 に限る)**

## この検証の最大の発見

**ハブは、接続先から受け取った回答を自分の `tone-and-format` で組み立て直している。**

ハブの指示には次のように明記してある。

> 接続先から受け取った内容をそのまま伝えてください。事実を足したり言い換えたりしないでください。

にもかかわらず、実際には再構成されている。人事エージェント単体では丁寧な文体も末尾の 1 文も正しく出ているのに、ハブを通ると落ちる。事実 (日数、条文番号) は保たれているが、**文体と体裁はハブ側のスキルが決めている。**

これで検証 B、C の結果もすべて説明がつく。

| 設定場所 | 利用者が直接その部門エージェントに聞く | 利用者がハブに聞く |
| --- | --- | --- |
| ハブのスキル | 該当なし | **効く** |
| ハブの指示| 該当なし | 効く (ただし体裁は tone-and-format が優先) |
| 部門のスキル | 起動することがある (不安定) | **効かない** |
| 部門の指示| **効く** | **効かない** |
| 部門のナレッジ ソース | 効く | **効く** (事実は保たれる) |

**ハブ + 部門エージェントという構成では、利用者に届く文面はすべてハブが決める。** 部門側に置けるのは「事実の出どころ」だけである。

## 設計への影響

部門ごとに振る舞いを変えたいなら、選択肢は 2 つしかない。

### 案 A: 共通スキルに部門ごとの節を持たせる (今回成立した方法)

- 変更は 1 か所 (ハブ) で済む
- **共通スキルに部門名が入る。** 部門が増えるたびに共通スキルを直すことになり、「ハブに部門名を書かない」という当初の設計方針は崩れる
- ただし崩れるのは指示ではなくスキルなので、正本の外に出す形は保たれる

### 案 B: 利用者が部門エージェントに直接アクセスする

- 部門の指示とスキルがそのまま効く
- ハブの振り分けを捨てることになる。利用者は自分で部門を選ぶ

今回の検証の範囲では **案 A を採る**。理由は、変更経路が 1 本 (正本の SKILL.md → ハブ) に保たれることである。部門名が共通スキルに入る点は、`## 部門ごとの文体` という節にまとめ、部門ごとの記述をその節の中だけに閉じることで影響を局所化する。

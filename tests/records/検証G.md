## G-1 ハブのプレビューは、部門の下書きと公開版のどちらを呼ぶか

### 構成

| エージェント | 内容 |
| --- | --- |
| 公開確認 部門 | 指示だけ。「合言葉を聞かれたら『今日の合言葉は『みかん』です。』と答える」。ナレッジなし、Web 検索なし |
| 公開確認 ハブ | 指示: 自分は合言葉を知らない。合言葉の質問は必ず部門に取り次ぎ、受け取った内容をそのまま伝える。スキルなし、ナレッジなし。未公開 (保存のみ) |

接続の説明は「今日の合言葉を知っているエージェント。合言葉に関する質問はすべてこのエージェントに取り次ぐ。」です。
質問は毎回「今日の合言葉を教えてください。」で、ハブ経由の回は毎回ページを開き直して新しい会話にしました。
モデルは 2 つとも Claude Opus 5.5 (既定) です。

### 結果

| 段階 | 部門の状態 | 部門に直接 | ハブ経由 (Used tool で見た部門の回答) |
| --- | --- | --- | --- |
| 0 | 指示 v1 (みかん) を公開 | - | みかん 3/3 |
| 1 | 指示を v2 (りんご) に変えて **[保存]** だけ | りんご | **みかん 3/3** |
| 2 | v2 を公開 | - | りんご 3/3 |
| 3a | 回答の末尾に「(整理番号 P-3-5521)」を書くスキル `aikotoba-reference-number` を **[最初から作成]** で追加し、**[保存]** だけ | りんご + 整理番号 (`Used skill:` あり) | **整理番号なし 3/3** |
| 3b | 3a を公開 | - | **りんご + 整理番号 3/3** (ハブの最終回答にも残った) |

段階 1 の 3 回目は、新しいチャットへの切り替えが効かず同じ会話の 2 問目になったため、数えずにやり直しました。

### 分かったこと

1. **ハブの [プレビュー] は、部門の公開版を呼ぶ。** 指示もスキルも、部門を公開し直すまでハブ経由には届かない。
2. **ハブの推論カードの `Used tool: <部門>` を開くと、部門に渡した依頼 (`task`) と、部門が返した回答 (`agent_response`) がそのまま見える。**
3. ハブにスキルがない構成では、部門にしかないスキルの効果がハブの最終回答まで届いた (3/3)。

## G-3 対照: ハブから tone-and-format を外す

ハブから `tone-and-format` (v4) だけを削除して保存しました (`escalation-rules` は残した)。人事はそのままです。

ハブは整理番号を「（人事部門の整理番号: F-1-7781）」「（整理番号 F-1-7781）」のように言い換えることはありましたが、落としてはいません。
この回、ハブの推論カードに `Used skill:` は出ませんでした。

その後、同じ構成 (`tone-and-format` なし) で [評価] タブから 4 問、[プレビュー] から 2 問を投げました。
[プレビュー] の「通勤手当の上限はいくらですか」の 1 回だけ、人事の回答には整理番号があるのに、ハブが回答を「結論、支給区分、補足、次にすること」に組み直して落としました。
`tone-and-format` を外した状態の通算は **15 回中 14 回** です。

| ハブの `tone-and-format` | ハブの最終回答に整理番号が届いた回数 |
| --- | --- |
| あり | 0/21 (G-2 の 9 回と、[評価] の 1 回目から 3 回目の人事の 4 問 × 3) |
| なし | 14/15 |

### 結論

- 部門にしかないスキルは、ハブから呼ばれたときも使われている。
- ハブに回答の見出しを決めるスキル (`tone-and-format`) があると、ハブは部門の回答をその見出し (結論、根拠、次にすること、受付時間) に当てはめて書き直し、どの見出しにも当てはまらない末尾の 1 文 (整理番号) を毎回落とした。
- そのスキルを外すと、ほとんどの回で届いた。ただし、ハブが自分で組み直して落とす回もあった。

## [評価] タブで同じ現象を測る

テスト方法「全般的な品質」で、`tests/eval_F再現.csv` の 5 問を 4 回流しました。
取り込み用テンプレートの注記には、`response` 列は参照用で、エージェントの回答とは比較しないと書かれています。

| 回 | ハブの構成 | 合格 | 整理番号がハブの最終回答に届いた (人事の 4 問) |
| --- | --- | --- | --- |
| 1 | `tone-and-format` あり | 5/5 | 0/4 |
| 2 | `tone-and-format` あり | 4/5 (B-01 が失敗) | 0/4 |
| 3 | `tone-and-format` あり | 4/5 (B-01 が失敗) | 0/4 |
| 4 | `tone-and-format` なし | 4/5 (B-01 が失敗) | 4/4 |

- **全般的な品質は、部門の内容がハブで落ちていることを検出しない。** 届いた回 (4 回目) と落ちた回 (1 から 3 回目) で、人事の 4 問の判定と理由は同じ (合格、「関連性があるように見えます」)。
- 結果の画面で分かるのは、ハブの最終回答と「Tools referenced」(スキルと接続エージェントの名前) まで。部門の回答は、部門の [履歴] (チャネル欄が「評価」) で確かめる。
- 設計どおりの引き継ぎ (B-01、退職に関わる質問を担当窓口へ回す) は、4 回中 3 回「未回答の質問が残っています」として失敗した。判定は実行ごとに揺れる。
- [評価] は保存済みの構成で動く。画面でスキルを削除しただけで保存が終わっていない状態では、削除前の構成で動いた (3 回目)。

## 取り次ぎ先の回答を確かめる方法

| 方法 | 見えるもの | 見えないもの |
| --- | --- | --- |
| ハブの推論カードの **Used tool** | ハブが部門に渡した依頼と、部門が返した回答 | 部門で使われたスキル。**エンド ユーザー プレビュー** をオンにしていると、依頼と回答も出ない |
| 部門エージェントの **[履歴]** | ハブから呼ばれた回のセッション (依頼文、部門の回答、消費したクレジット) | `Used skill:` の行 |
| App Insights (環境レベルのテレメトリ、プレビュー) | ハブ → 部門 → ナレッジ検索のつながりと、各段の入出力 | スキルの読み込み |

### App Insights で見えたもの

Power Platform 管理センターのデータのエクスポートで、環境のテレメトリを Application Insights に送りました ([Environment-level telemetry with Application Insights (preview) (英語)](https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-environment-level-agent-telemetry))。
マネージド環境が前提です。
エクスポートを作ってから 20 分から 40 分後の会話は届かず、約 27 時間後に [プレビュー] で投げた 2 問の分が届きました。

1 問 (1 ターン) は、`dependencies` テーブルの次のスパンになりました。

```text
InvokeAgent  ハブ                          (ルート)
├ ExecuteTool  人事 (gen_ai.tool.type = agent)  … tool.call.arguments に依頼、tool.call.result に人事の回答
│ └ InvokeAgent  人事
│    ├ ExecuteTool  DataverseFileAttachment × 3 から 6  … ナレッジの検索
│    └ OutputMessages  人事                 … 人事の回答
└ OutputMessages  ハブ                       … 利用者への最終回答
```

ハブと人事のスパンは同じ `operation_Id` でつながり、`operation_ParentId` で親子をたどれます。

| 質問 | ハブの ExecuteTool の結果 (人事が返した回答) | 人事の OutputMessages | ハブの OutputMessages (最終回答) |
| --- | --- | --- | --- |
| 有給は半日単位で取れますか | 整理番号あり | あり | あり |
| 通勤手当の上限はいくらですか | 整理番号あり | あり | **なし** |

テレメトリだけで、どの段で内容が落ちたかを特定できました。
一方、スキルの名前はどのスパンにも出てきません。
属性の中の日本語は `\uXXXX` の形にエスケープされているため、日本語の文字列で `contains` を使っても当たりません。英数字 (この検証では整理番号) で探します。

```kusto
dependencies
| where timestamp > ago(3d)
| order by timestamp asc
| extend cd = customDimensions
| project t = format_datetime(timestamp, 'HH:mm:ss'), name,
    agent = tostring(cd['gen_ai.agent.name']), tool = tostring(cd['gen_ai.tool.name']),
    op = operation_Id, id, parent = operation_ParentId,
    resultHasSerial = tostring(cd['gen_ai.tool.call.result']) contains 'F-1-7781',
    outputHasSerial = tostring(cd['gen_ai.output.messages']) contains 'F-1-7781'
```

## 判定

| 問い | 答え |
| --- | --- |
| 部門にしかないスキルは、ハブから呼ばれたときに使われるか | 使われる (G-2、G-3 で 9/9 ずつ) |
| ハブ経由の回答に効果が届かなかったのはなぜか | ハブが回答を組み直すときに落とした。回答の構成を決めるスキルがあると毎回落ちた |
| ハブのプレビューは部門の何を呼ぶか | 公開版 |
| 取り次ぎ先で何が起きたかを確かめられるか | Used tool、部門の [履歴]、App Insights で確かめられる。ただし、部門で使われたスキルはどれでも見えない |
